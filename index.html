5 · AI Prompts

Prompt A — สร้างเว็บทดสอบ

You are a senior front-end developer helping a QA engineer.

Build a small practice web app I can use to train manual and automated testing.
Requirements:
- Plain HTML, CSS, and vanilla JavaScript only. No frameworks, no build step.
- Pages: login, product list with search and filter, shopping cart, checkout form.
- Use stable, test-friendly attributes: add data-testid to every interactive element.
- Include realistic validation: required fields, email format, min/max quantity,
  card number length, and a clear error message area.
- Intentionally include 3 subtle bugs and list them separately at the end so I can
  practise finding them (do not fix them in the code).
- Store the cart in localStorage so state survives a page reload.

Create each file one by one and explain the folder structure first.

Prompt B — แปลง test case เป็น Playwright

Act as a test automation engineer.

Here are my manual test cases written in English:
"""
TC-01 Verify that a user can log in with valid credentials.
TC-02 Verify that an error message appears when the password is empty.
TC-03 Verify that a product can be added to the cart and the badge count increases.
"""

Convert them into Playwright tests in JavaScript.
Rules:
- Use data-testid selectors, never brittle XPath.
- One describe block per feature, clear test titles in plain English.
- Add meaningful assertions, not just "is visible".
- Add a short comment above each test explaining what risk it covers.
Then tell me which additional edge cases I am missing.

Prompt C — ให้ AI อธิบาย error

I ran this command in VS Code terminal and got an error.

Command: """npx playwright test"""
Error: """[paste the full error here]"""

Please:
1. Explain in simple English what this error means.
2. Give me the exact commands to fix it, step by step.
3. Tell me how to avoid this next time.

Prompt D — รีวิวโค้ดในมุม QA

Review this code from a QA perspective, not a developer perspective.

"""[paste your code]"""

Tell me:
1. Which parts are hard to test and why.
2. Which selectors are fragile for automation.
3. What validation or error handling is missing.
4. Five test scenarios I should write for this code.
Answer in clear professional English.

7 · Playwright

ติดตั้ง

npm init -y
npm init playwright@latest
# ตอบ: JavaScript → tests → GitHub Actions? No → install browsers? Yes

ตัวอย่าง tests/login.spec.js

const { test, expect } = require('@playwright/test');

test.describe('Login page', () => {

  test.beforeEach(async ({ page }) => {
    await page.goto('http://localhost:3000/pages/login.html');
  });

  // Covers the main happy path of authentication
  test('user can log in with valid credentials', async ({ page }) => {
    await page.getByTestId('username').fill('tester@example.com');
    await page.getByTestId('password').fill('Password123');
    await page.getByTestId('login-btn').click();
    await expect(page.getByTestId('welcome-message')).toContainText('Welcome');
  });

  // Covers validation when a required field is empty
  test('shows an error when the password is empty', async ({ page }) => {
    await page.getByTestId('username').fill('tester@example.com');
    await page.getByTestId('login-btn').click();
    await expect(page.getByTestId('error-message'))
      .toHaveText('Password is required.');
  });

});

คำสั่งที่ใช้บ่อย

Commandความหมาย
npx playwright testรันเทสทั้งหมดแบบ headless
npx playwright test --headedรันแบบเห็นเบราว์เซอร์จริง
npx playwright test --uiโหมด UI ไล่ดูทีละ step ย้อนเวลาได้
npx playwright test --debugดีบักทีละบรรทัด
npx playwright codegen localhost:3000บันทึกการคลิกแล้วแปลงเป็นโค้ด
npx playwright show-reportเปิดรายงานพร้อม screenshot และ trace

9 · Troubleshooting

อาการวิธีแก้
'node' is not recognizedยังไม่ได้ติดตั้ง Node หรือยังไม่ restart terminal
EADDRINUSE: port 3000พอร์ตถูกใช้อยู่ — เปลี่ยนเป็น 3001 หรือปิด process เดิม
หน้าเว็บไม่อัปเดตกด Ctrl+Shift+R hard refresh ล้าง cache
CORS error ตอน fetchอย่าเปิดแบบ file:// ให้รันผ่าน local server
Playwright หา element ไม่เจอตรวจว่า server รันอยู่ และ data-testid ตรงกัน
Test flakyเลี่ยง waitForTimeout ใช้ expect(...).toBeVisible() แทน
AI เขียนโค้ดแล้วพังวาง error เต็มๆ กลับไปให้ AI พร้อมบอกไฟล์และบรรทัด
